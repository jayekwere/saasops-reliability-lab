# Threat model

Protect probe destination authority, tenant investigations, recovery configuration, approval independence, evidence integrity and availability. Clients, incident notes, DNS results and network responses are untrusted. Trust the issuer, registry, operator catalog, system certificate roots and service host. A network result is bounded evidence, not a business verdict.

| Threat                                                            | Control and evidence                                                                                                               | Residual limit                                                            |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Client chooses internal URL or leaks credentials through redirect | No API target input, HTTPS configuration, no URL credentials/query/fragment, address range validation, pinned socket, no redirects | Operator configuration, public routing and egress still require review    |
| Forged role or cross-tenant investigation access                  | Signed claims, server registry, tenant storage predicates and negative tests                                                       | Host/issuer compromise remains outside local isolation                    |
| Insecure TLS hides an outage                                      | Trust/hostname verification and real trusted/untrusted/mismatch/expiry-threshold tests                                             | One observed endpoint is not all user access                              |
| Missing probes create false uptime                                | Unknown/no-data states, incomplete-window labels, sample-based math and gap checks                                                 | A probe SLI is not time-based or user-request availability                |
| Premature or repeated incident closure                            | State/version checks and two fresh successes after detection                                                                       | A recovered probe does not establish root cause or full business recovery |
| Malicious note runs in the workbench                              | Text-node rendering and restrictive CSP                                                                                            | Notes still require appropriate operational privacy                       |
| Edited/stale backup redirects service behavior                    | Domain-separated signature, exact before-state/digest, server-originated backups and independent approval                          | A compromised host or audit key can forge local evidence                  |
| Duplicate restore mutates again                                   | Local transaction, key/actor binding, persisted readback and replay tests                                                          | This does not restore a remote provider                                   |
| Probe or evidence workload exhausts resources                     | Bounded catalog, deadlines, rates, serialization, record caps, protected evidence retention and hard audit capacity                | Long-running operations need archive, disk monitoring and a suitable edge |

Security invariants: a request cannot choose a network destination; configured probes never silently disable certificate checks or follow redirects; a viewer cannot mutate; an incomplete window is not presented as measured global uptime; closure requires specific fresh success; restore is exact and independently approved; incident-referenced observations survive pruning. Independent audit checkpoints and a reviewed deployment remain necessary for stronger guarantees.
